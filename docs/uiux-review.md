# ReportBinder UI/UX レビュー（2026-11-03）

対象: `app/web/`（index.html / app.js / style.css）、版 `2026.10.30.32`（app.js?v=20261030_v220 / style.css?v=20261030_v131）。

## 全体の印象

- 見た目は一貫している。色・余白・角丸がトークン化され、14px 未満の文字が無いことまで門で守られている。

## P0（利用者が先に進めなくなる・誤解する）

### P0-1 原稿の登録に失敗すると、理由がどこにも表示されない

- 再現: 原稿を選んで「選択した原稿を登録」→ 全件失敗 → トースト「登録できませんでした／詳細を確認してください。」が出る。
- 「詳細」はどこにもない。`showMessage('warn', …, detail)` は `detail` を非表示の `<pre id="log" hidden>` に書くだけで、画面にもエラーパネルにも出さない（`app.js` `registerSelected`）。
- 今回の実際の理由は「PDF原稿の取り込みに必要なPDFBoxまたはJava Runtimeが見つかりません。」だった。`userFriendlyError` にはこの文言に対する案内（「情報システム担当者に『ReportBinderのセットアップ』の実行を依頼してください」）まで用意されているのに、使われていない。
- 一部だけ失敗したとき（「n件を登録しました／m件は登録できませんでした。」）も同じで、**どのファイルがなぜ**失敗したかが分からない。
- あわせて、失敗後にチェックがすべて外れるため、やり直すには選び直しが必要。
- **対応**: 失敗理由を（同じ理由はまとめて）トースト本文に出し、失敗したファイルは選択したまま残す。

## P1（つまずき・不整合。小さく直せる）

### P1-1 何も始めていないのに、ステップ1が「!」（要対応）になる

- 初回起動直後、原稿が0件の段階で上部の進捗「1 原稿を登録・PDF化」が警告色の「!」になる。ステップ2・3は「2」「3」の数字のまま。
- 「何か壊れているのか」と受け取られやすい。0件は「まだ始めていない」状態であって、要対応ではない。
- **対応**: 登録済み原稿が0件のときは数字「1」を出す。登録済みで変換待ちがあるときだけ「!」。

### P1-2 操作のあと、選択0件でも「選択した原稿を登録」が押せる状態に戻る

- `runBusy` の `finally` がボタンを無条件に `disabled=false` に戻すため、登録後（成功・失敗とも）選択0件なのにボタンが有効色になる。押すと「原稿を選択してください」と言われる。
- **対応**: 登録処理のあとで選択状態に合わせてボタンを同期し直す。

### P1-3 原稿フォルダーの表示が末尾で切れ、肝心のフォルダー名が見えない

- `.source-folder-bar strong` が1行・末尾省略のため、長いパス（共有フォルダーでは普通）だと `…\8acfcb24-4c99-4bbf-b8bb-bd…` のように**最後のフォルダー名が隠れる**。「どのフォルダーを見ているか」を確かめる場所なので、末尾こそ見えるべき。
- **対応**: 省略せず折り返して全体を表示する（ツールチップは既にある）。

### P1-4 「一式」と「パック」の呼び名が混在

- 一式の切り替えメニューの見出しが「一式／使用する**パック**を選択します」。他はすべて「一式」。`selfcheck.py` も「同じものを3通りに呼ばない」方針で「資料パック」を禁止している。
- **対応**: 「使用する一式を選びます」に改め、`index.html` に「パック」が戻らないよう門に足す。

### P1-5 ページ構成の操作バーで「変更分のみ」「ページをクリックして選ぶと移動できます」が1〜2文字ずつ折り返す

- 1422px 幅で、操作バー（`#page-command-bar`、意図的に1行＋横スクロール）が収まらず、チェックボックスのラベルと案内文が縦に潰れて折り返す（「変更分の／み」「ページをクリッ／クして選ぶと移／動できます」）。横スクロールバーも出ている。
- **対応**: 1行固定の方針は保ったまま、「変更分のみ」のラベルだけ折り返さない（`white-space:nowrap`）。案内文にも同じ指定を試したが、1行に固定すると隣の「選べるページがありません」ボタンに隠れて「ページをクリック」までしか見えなくなったため、案内文は折り返しを許したままにした（根本対応は下の needs-owner-decision）。

### P1-6 変更履歴・比較で、原稿が0件のとき「選択してください」しか出ない

- プルダウンの中身が空（「選択してください」だけ）で、下に「対象原稿を選ぶと、版の一覧・差分・保護を表示します。」と出る。選べるものが無いことも、どうすれば選べるようになるかも書かれていない。
- **対応**: 0件のときは「まだ原稿が登録されていません。『原稿を登録・PDF化』で原稿を登録すると、ここで版を比べられます。」と出す。

### P1-7 PDFプレビューの iframe の title が英語（"PDF preview"）

- 画面読み上げで英語が読まれる。他の aria-label はすべて日本語。
- **対応**: 「PDFプレビュー」に。

## P2（気になるが急がない）

- **P2-1 ホームに進捗表示が2つある**: 上部の進捗バー（1→2→3）と、ホームの「原稿を集める→順番を整える→1つのPDFにする」が同じ内容を別の言葉で並べている。しかも呼び名が少しずつ違う（後述 P2-2）。
- **P2-2 同じ段階の呼び名が画面ごとに違う**: サイドバー「ページ構成」／進捗「順番を整える」／ホーム「順番を整える」。サイドバー「提出用PDF」／進捗「提出用PDFを出力」／画面見出し「提出用PDFを作る」／ホーム「1つのPDFにする」。どれも意味は通じるが、「同じ物か確信が持てない」状態を生む。→ needs-owner-decision（下記）。
- **P2-3 一式作成ダイアログで「今回まとめる一式」が3回続く**（小見出し・見出し・入力欄ラベル）。小見出しは削ってよい。
- **P2-4 未登録原稿の並びが更新日時の新しい順**: 「01_表紙」「02_…」と番号付きで管理している利用者には、名前順のほうが登録漏れに気づきやすい。並び替えの切り替えがあるとよい。
- **P2-5 一式が未作成のとき、上部の「未作成」ボタンが塗りつぶしの主ボタン色**: 「今回まとめる一式：未作成」が状態表示なのに、押すべきボタンに見える（実際押すと一式メニューが開くので誤りではない）。
- **P2-6 原稿が0件でも「変換PDFをすべて作り直す」が見出し右に常に出ている**。押しても何も起きない操作は、0件のときは隠すか無効にしたい。
- **P2-7 ページ構成の案内文が長い**: 「まず行うこと」帯の説明（Ctrl/Shift クリック・ペン・タッチ・ダブルクリック）が1段落に詰め込まれ、老眼の利用者には読み切れない。キーボード操作の一覧は「表示・履歴」の中にもあり重複している。
- **P2-8 `style.css` の後段に上書きの層が積み重なっている**（`.page-command-bar` だけで10箇所以上、`!important` 19件、`@media` 58件）。今回の P1-5 のような崩れは、どの規則が勝っているかを追うのに時間がかかる。整理は大きな作業になるため needs-owner-decision。

## needs-owner-decision（今回は手を付けない）

| 項目 | 理由 |
| --- | --- |
| 段階の呼び名の統一（P2-2） | どれを正にするか（「ページ構成」か「順番を整える」か）は製品の言葉の決定。`selfcheck.py` が多数の文言を固定しているため、一括で変える判断が要る。 |
| ホームの重複した流れ図の削除（P2-1） | 初回利用者向けの説明として意図して置いている可能性がある。 |
| 未登録原稿の並び順（P2-4） | 「新しく置いたファイルを上に」が意図されている可能性がある。既定を変えるか、切り替えを足すかの判断。 |
| ページ構成の操作バーを2段にする（P1-5 の根本対応） | `style.css` 759行目付近に「デスクトップでは1行に保つ」と明記された設計判断。今回は折り返しの潰れだけ直す。 |
| `style.css` の上書き層の整理（P2-8） | 全画面の見た目に波及する大きな作業。視覚回帰の仕組みが無い状態では危険。 |
| 警告トースト全般で `detail` を画面に出すか | 今回は登録だけ直した。他の `warn`＋`detail` 呼び出し（PDF作成の中止、出力後の追加対応など）は本文に理由を含めているが、共通の「詳細を見る」導線を作るかは設計判断。 |
