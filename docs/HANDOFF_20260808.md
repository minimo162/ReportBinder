- 起動入口: `資料をPDFにまとめる.cmd`

このブランチでは、ECM専用の管理ツールから、複数部署のExcel・Word・PowerPoint・PDFを資料パックとしてまとめ、更新履歴とPDF差分を確認できる汎用アプリへ移行した。

## 2. 確定した製品方針

- 管理単位は「資料パック」のみ。日本語管理・英語管理などの別ワークスペースは持たない。
- 表紙、目次、区切りページはアプリが自動生成せず、通常の原稿として登録してページ構成で配置する。
- 原稿や履歴、ページ構成、出力は利用者ごとのローカル領域に保存する。共有フォルダは原稿の受け渡しと明示的な発行先として扱う。
- 通常の利用者には内部ファイル名、管理構造、診断操作を見せない。復旧用操作は必要な場合だけ折りたたんで表示する。
- 画面は「原稿を登録・PDF化」→「ページ構成」→「最終PDF」の3工程を基本とし、「変更履歴・比較」は随時使う確認機能とする。

## 3. このブランチの主な変更

### 差分・履歴

- 途中ページの追加・削除でページ番号だけを比較せず、外周を除いた画像シグネチャと文書順序を使う動的計画法で論理ページを対応付ける。
- 自動フッター番号、全面テンプレート変更、重複ページ、スキャンノイズを含む難例を追加検証した。
- 対応を断定できない区間は誤った「変更」とせず「対応不確実」として目視確認を促す。
- 画像距離計算をC#へ移し、長文書の比較時間を短縮した。
- PDF作成直後に履歴要約を再集計し、保存済み画像ハッシュを任意2世代比較ですぐ利用できるようにした。旧キャッシュもスキーマ更新時に再集計する。

### 原稿・資料パック・出力

- Excel、Word、PowerPoint、PDFを同じ資料パックに登録できる。
- ECM/BOD/DMMの初期資料パックとひな形を通常UIから外し、完全新規時は0件から開始する。
- 必須原稿の未作成、更新あり、変換失敗、ファイル欠落は最終出力をブロックする。
- 原稿の担当部署、必須、追加ページ配置などは通常画面から折りたたみ、影響を平易な文で説明する。
- ページ構成はカード選択と移動先ボタンを主操作にし、複数移動、移動漏れの追加、Undo/Redoを維持した。

### UI・アクセシビリティ

- 原稿フォルダ専用タブを廃止し、フォルダ選択と変更を「原稿を登録・PDF化」へ統合した。
- 初回から左ナビを固定し、3工程の現在地が変わらないようにした。
- 起動待ちとデータ読込待ちを同じ画面へ統合し、読込前の空データ画面を表示しない。
- 元ファイル更新の警告を強く、作成済みPDFの見た目差分を控えめに表示する。詳細は「変更履歴・比較」に集約した。
- ページ構成はタブと幅広いサムネイルグリッド、最終PDFは未解決タスク優先の状態別UIへ整理した。
- 英数字はSegoe UI、日本語はBIZ UDPゴシックを基準にした。本文16pxを基準とし、フォーカスリング、入力ラベル、チェック操作領域、スキップリンクを改善した。
- 右上メニューに安全な終了操作を配置した。

### 起動・配布

- 起動入口を `資料をPDFにまとめる.cmd` に統一し、日本語管理・英語管理と互換用入口を削除した。
- ランチャーはローカルruntimeへ展開して起動し、待機画面から自動的にアプリへ移る。
- stop処理は実行中インスタンスを識別して停止する。

## 4. 検証結果

### 差分難例

独立した一時環境で、管理レポート、監査報告、印刷申請フォーム、横長工程・品質資料の4系統×4世代、計16 PDF・49ページを生成して検証した。

- 36比較、115比較レコード、`unknown=0`
- 局所的な意味差分: 20/20検出
- 構造対応: 6/6合格
- 正方向・逆方向: 8/8合格
- 同一版比較: 4/4で差分領域0
- 220ページ文書の比較を含む長文書回帰を追加

再現可能なコーパス生成・検証は次に含まれる。

- `app/tools/create-pdf-diff-corpus.py`
- `app/tools/pdf-diff-corpus-selfcheck.ps1`
- `tests/pdf-diff-corpus.mjs`
- `docs/PDF_DIFF_CORPUS.md`

### UX

完全新規の別設定領域を使い、高齢でPC操作に不慣れな多忙な管理職と、前任者のいない新入社員を想定して独立実機評価を実施した。初回フォルダ設定、資料パック命名、登録、PDF化、更新検出、2世代比較、ページ構成、最終出力、終了まで完遂し、重大・高優先度の問題は解消した。修正後の独立評価は9/10。

## 5. 保守時に守る判断基準

- 「PDFを作れた」より「必要な原稿を落とさず提出できた」を優先する。
- 実行不能な主ボタンより、先に解消すべき問題を強く表示する。
- 同じ情報を複数画面で競わせない。登録画面は最新状態の要約、履歴画面は任意2世代の詳細比較を担当する。
- 初見利用者へ内部語を出さない。`structure.json`、画像ハッシュ、content-pdfなどは診断情報に限定する。
- 差分で確信がない場合は断定せず、左右PDFの目視確認へ案内する。
- 画面追加より、既存工程への統合と段階表示を優先する。

## 7. GitHubと作業データ

- GitのpushはWindows資格情報マネージャーを使用する方針。
- GitHub CLIの保存済み認証が無効な場合は、トークン値を表示・コピーせず、Windows資格情報または接続済みGitHub機能を使う。
