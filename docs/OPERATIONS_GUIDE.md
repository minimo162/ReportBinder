# ReportBinder 配布・移行・運用ガイド

対象は ReportBinder V5 の管理者と導入担当者です。原稿そのものを変更せず、利用者ごとのローカル管理領域で履歴・変換PDF・ページ構成を管理します。

## 1. 配布版の選択

| 配布物 | 用途 | Java |
|---|---|---|
| オフライン完結版 | インターネットへ接続できないPC、社内配布の標準 | 同梱 |
| オンライン導入版 | 初回だけ依存物を取得できるPC | 初回導入時に取得 |
| 共有フォルダー用完成フォルダー | 管理者が完成物を共有し、各PCへコピーして使う場合 | 同梱 |

配布物のルートにある `release-manifest.json` で、配布種別、作成日時、Java同梱有無、PDFBoxと組版jarのSHA-256を確認できます。利用者は共有フォルダー上で直接実行せず、フォルダー全体をローカルへコピーしてから `資料をPDFにまとめる.cmd` を起動してください。資料パックが唯一の管理単位であり、日本語・英語などの用途は資料パック名やひな形で分けます。

## 2. 導入前の確認

1. Windows へ通常のデスクトップユーザーとしてサインインする。
2. Excel原稿を使うPCには Microsoft Excel 16.x以降、Word原稿には Microsoft Word 16.x以降、PowerPoint原稿には Microsoft PowerPoint 16.x以降を用意する。PDF原稿だけならOfficeは不要。
3. ReportBinderを起動し、`提出フォルダー`画面の`動作環境の診断`を実行する。
4. PDF処理エンジンが利用可能であること、保存先が設定済みであることを確認する。
5. Excel、Word、PowerPointが`登録済みだが起動不可`の場合は、Windowsへサインインし直してデスクトップから再実行する。サービスアカウントや非対話セッションからOffice COMを起動しない。

診断が`制限あり`でもPDF原稿は継続利用できます。`修復が必要`の場合は配布物を再展開し、`release-manifest.json`と同梱ファイルを管理者が照合してください。

## 3. 既存ECM/BOD/DMM案件の移行

### 利用者の手順

1. 念のため、現在の提出フォルダーと必要な最終PDFをバックアップする。
2. 新しいReportBinderをローカルへ展開して起動する。
3. 以前と同じ提出フォルダーを選択する。原稿ファイルや提出フォルダー内の旧 `_reportbinder` は移動・改名しない。
4. 既存のローカル管理データがあるPCでは、そのまま同じページ順・本体/補足・ECM/BOD/DMM設定を確認する。
5. `動作環境の診断`、`更新を確認`、提出用PDF画面の`出力前チェック`を順に実行する。出力前チェックでは、必須原稿、変換PDF、未振り分けページ、必須出力先、仕上げ設定が一画面に表示される。問題がある項目は`確認する`から該当工程へ戻る。

schema 1/2 の `structure.json` は初回ロード時に schema 3へ自動移行します。移行前データは同じワークスペースへ `structure.json.v1.bak` または `structure.json.v2.bak` として保存し、`schema-version.json` に完了版を記録します。再起動しても同じ移行を繰り返しません。

### 移行後の確認項目

- 登録原稿数と原稿名
- ECM/BOD/DMMごとの本体・補足の項目数と順序
- 出力対象外の項目
- ページ番号、表紙、目次、区切り、ページ範囲
- 最終PDF名と出力先
- 任意の過去2版を選んだ差分表示と、項目判定・対応確信度を含む差分レポートCSV

移行警告が表示された場合は、元のバックアップを削除せず、警告対象だけをページ構成画面で確認してください。

## 4. 障害時の復旧

### 最終PDF作成中にアプリやPCが終了した場合

次回起動時にトランザクション記録と実ファイルのSHA-256を照合します。ReportBinder自身が差し替えた途中状態と判定できた場合だけ、直前の最終PDFへ自動的に戻し、一時PDFと使用済みバックアップを削除します。

出力先PDFが利用者または別アプリによって変更され、記録済みの新旧どちらのSHA-256にも一致しない場合は、自動上書きせず `manual-recovery-required` として停止します。この場合は次の順で対応します。

1. ReportBinderを終了する。
2. 現在の出力PDF、`state\final-transactions`、対応する`state\final-backups`を別の安全な場所へコピーする。
3. 利用者が残したいPDFを確認する。
4. 管理者判断で旧版を戻すか、現在の原稿とページ構成から最終PDFを再作成する。

### 同時利用

構成更新と最終出力はファイルハンドルによる排他ロックを使います。別PCが処理中なら二重更新せず待機または失敗します。強制終了後に空の `.lock` ファイルが残っても、所有ハンドルが解放されれば再取得できます。ロックファイルだけを見て手動削除する必要はありません。

## 5. 自動PDF作成とOffice原稿の安全設定

自動PDF作成は既定で無効です。原稿画面の設定から有効にすると、更新検出後の静止待ち、失敗時の再試行回数、処理に必要な最小空き容量、完了・失敗通知を変更できます。再試行は待ち時間を段階的に延ばし、上限へ達した同じ原稿版を繰り返し実行しません。利用者が原稿を修正して保存し、新しいハッシュになった場合は自動的に待機状態へ復帰します。

手動のPDF作成中は進捗欄から中止できます。中止要求後は現在処理中の原稿を安全に完了してから、未処理の原稿を残して停止します。すでに完成した変換PDFとページ構成は巻き戻しません。中止後は残った原稿を選択して再度PDF作成できます。

空き容量が設定値未満の場合は原稿を失敗扱いにせず`disk-low`で保留します。容量を確保した後は同じ版を再評価します。Excelを編集中の場合も変換を保留し、保存・終了後に処理します。

`.xlsm`は通常のExcel原稿として登録できますが、ReportBinderはマクロを実行しません。Excel COMを起動するときにAutomation Securityを強制し、イベントと外部リンク更新を無効にします。マクロ実行結果に依存する帳票は、利用者がExcel上で値を確定・保存してから登録してください。

`.docx`と`.pptx`も一時コピーを専用COMワーカーで読み取り専用に開き、Automation Securityを強制します。`.docm`と`.pptm`は登録対象外です。Word/PowerPointの変換が120秒以内に終わらない場合はその原稿だけをエラーにし、前回成功した変換PDFを保持します。強制終了するのはReportBinderが起動した所有プロセスだけです。

## 6. 容量見積もり

標準設定は原稿5世代、変換PDF3世代、履歴のソフト上限5,120 MB、警告80%です。実際の必要量は原稿形式、画像解像度、シート数、更新頻度で変わるため、代表案件を1回変換して測定してください。

1案件・1利用者あたりの計画値は、次の式を目安にします。

```text
計画容量 = (原稿一式 S × 5世代) + (変換PDF一式 P × 3世代) + 比較/管理データ C + 20%余裕
```

例として、原稿一式200 MB、変換PDF一式120 MB、比較/管理データ200 MBなら、`(200×5) + (120×3) + 200 = 1,560 MB`、20%を加えて約1.9 GBです。これは例示であり、実測値を優先してください。複数利用者が同じ提出フォルダーを使っても履歴・変換PDFは利用者ごとのローカル領域にあるため、PC台数分を見積もります。

運用開始時は次を監視します。

- `%LOCALAPPDATA%\ReportBinder\projects` の合計サイズ
- 診断画面に表示される管理データ・出力先の空き容量
- 履歴容量警告
- 大容量案件の変換所要時間と最終PDFサイズ

リリース受け入れでは[`SCALE_BENCHMARK.md`](SCALE_BENCHMARK.md)のlargeティアを、Excel・Word・PowerPointを起動できる対話Windowsセッションで実行します。初回変換、各形式の更新検出、更新原稿だけの再変換、最終出力、ピーク作業領域、処理中の最小空き容量をJSONで保存し、前回値からの大幅な悪化がないか確認します。試験用原稿生成ツールと実測JSONは開発用であり、配布物には含めません。

## 7. リリース前の管理者チェック

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\app\tools\operational-readiness-selfcheck.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\app\tools\package-release.ps1 -OutputDir "D:\ReportBinderRelease" -NoOpen
```

配布物を展開後、文章中心、複数表、履歴書型帳票、縦横混在、複数スライドの代表原稿で、登録、変換、更新検出、再変換、ページ移動、任意2版差分、最終出力を確認します。Office原稿のE2Eは、Excel/Word/PowerPointを対話セッションで実際に起動できるPCで行ってください。
