# 開発の決まりごと

このリポジトリで繰り返し痛い目を見たことだけを書いています。一般論は書きません。

## 1. 新しい仕組みを足したら、それを疑う工程を必ず挟む

**新しく足した「安全のための仕組み」が、それ自体で正常動作を壊すことがあります。** 足した本人は、その仕組みが守るはずの筋道しか試さないため、自分では気づけません。

### 実際に起きたこと（2026-08-09 〜 2026-08-10）

| 足した仕組み | 足した直後の状態 |
| --- | --- |
| 外部コマンドの待ち時間の上限 | 呼び出し9箇所すべてが既定の120秒。コード自身が許容する2000ページのPDF分割が上限に触れ、**健全なファイルに「破損していないか確認してください」と表示**していた。返り値の `timedOut` はどこからも読まれていなかった |
| Excel変換の監視プロセス | 心拍を打つのが単発変換の経路だけで、2シート以上で既定になる一括書き出しには無かった。監視は実質「Excelの起動からの経過」を測っており、**5分を超える正常な変換で健全なExcelを強制終了**していた |
| CIの配分変更 | 利用者データを不可逆に壊しうるスキーマ移行の検査を、外部依存ゼロ・1.7秒なのに毎回の門から外していた。重いスイートを自動で走らせる経路が一つも無くなっていた |

いずれも実機テストは行っており、そのテストは通っていました。**試したのが自分の想定した筋道だけだったため**です。

### やること

新しい仕組み（監視、上限、再試行、フォールバック、ロック、キャッシュなど）を足したら、マージ前に次を通してください。

1. **主経路を数える。** その仕組みが働く経路と、実際に利用者が最も通る経路が同じか確認する。違うなら、そこを試していない。
2. **正常な重い入力で試す。** 上限や監視は「異常を止める」ために入れますが、壊すのはたいてい**正常だが重い**入力です。コードが許容している上限（2000ページ、シート数、共有フォルダー宛ての出力）で試す。
3. **敵対的にレビューさせる。** 「この変更が新たに壊したものを探せ、好意的に読むな」と指示する。件数を埋めさせず、疑って問題が無かった箇所も述べさせる。
4. **並行と後始末を疑う。** 状態を `$Script:` の1組で持っていないか。片付けが呼ばれない経路はないか。作業ファイルは消えるか。強制終了された後はどうなるか。

## 2. 追加した検査は、必ず落ちることを確かめる

検査を足しただけでは、それが機能している証拠になりません。**このリポジトリでは、書いた検査が空振りしていた例が繰り返し出ています。**

- 存在しない関数名で照合し、常に素通りしていた
- 片付けの行（`= $null`）に一致して、公開されているかを見ていなかった
- `selfcheck.py` 自身の必須ファイル一覧に名前があるため、常に一致していた
- **到達しないコード（`Build-FinalPdfLegacy`）を検査していた。** これを消したとき、同じく死にコードを見ていた検査が他に4件見つかった
- 存在しないパスで境界の検査を試し、境界を外しても別の理由で例外になっていた

### やること

検査を足したら、**その検査が守る性質をわざと壊し、意図した文言で落ちることを確認**してから進める。落ちなければ、その検査は無いのと同じです。壊し方は、実際に起こりうる形を選んでください（例：ページ配列を消すのではなく、出力先の振り分けを消す。前者は構造の同期で復元されるため検知できません）。

## 3. 対応しないと決めたこと

再提案を避けるために残します。必要になったら、この記述ごと見直してください。

### 原稿フォルダーのサブフォルダー探索

**しません。** 原稿フォルダーの直下には既定で `data` / `output` の子フォルダーが作られる設計です（`Get-DefaultChildPaths`）。再帰にすると自分の出力PDFを原稿として拾います。除外リストを持ち込むと、`relativePath` を主キーにしている登録・パス検証・重複判定の全体に波及します。

代わりに、原稿が見つからないときは**なぜ見つからないか**を画面に出しています（「このフォルダーの直下に原稿が見つかりません。サブフォルダーの中は探しません。」）。

### 旧形式（.xls / .doc / .ppt）の登録

**しません。** 列挙を足すだけでは終わらず、`Prepare-XlsxPrintPackage` が `.xlsx/.xlsm/.xltx/.xltm` 以外を素通りするため印刷設定の事前適用が効かず、遅く不安定なCOM経路に落ちます。事務職向けの道具に「登録はできるが変換がときどき失敗する形式」を増やすのは割に合いません。

### `workbookId` の付け替え時のリネーム

**しません。** `workbookId` は `content-pdf\` `input-history\` `locks\` のディレクトリ名そのもので、JSON内の相対パス文字列にも埋まっています。整合させる作業の途中で失敗すると、変換PDFと履歴が行方不明になります。IDからファイル名を逆算している箇所は無いので、据え置いたまま参照先だけ差し替えれば足ります。
