# 履歴管理ロジック レビュー記録（2026-08-07）

## 対象

入力検知版、保持原稿、レンダリング世代、シート別PDF、差分比較用pin/lease、保持整理、ページ構成履歴の保存・プレビュー・復元を対象に、実装と回帰テストを照合した。

## 守る不変条件

1. `manifest.json` が完成マーカーであり、未完成フォルダは履歴世代として扱わない。
2. 検知版の原稿を再利用または描画する前に、manifestの`sourceHash`と実ファイルのSHA-256が一致する。
3. 削除済みのmanifest、画像ハッシュ、シート別PDFをキャッシュだけで利用可能と判定しない。
4. pin/leaseは存在する履歴資産だけに作成し、保持整理と保護操作を同じロックで直列化する。
5. 現在版、最終出力、比較基準、直近比較、処理中leaseに使われる世代は保持数とは独立して保護する。
6. ページ構成履歴はレイアウト項目だけを保存・復元し、原稿状態や変換結果を巻き戻さない。
7. 復元前のページ構成を同一構造ロック内で保存できない場合は、復元自体を行わない。
8. 現在の資料パックに存在しない出力先を履歴から復活させず、対象ページを未振り分けへ戻す。

## 修正した問題

- manifest、画像ハッシュ、シート別PDF索引のキャッシュが、背後のファイル削除後も古い値を返す経路を修正した。
- 保持原稿の既存ファイルを無条件再利用していた処理をSHA-256検証付きにし、破損原稿を描画入力として返さないようにした。
- 未完成フォルダを保持世代数へ含めていたため、完成世代を予定より早く整理する可能性を解消した。
- 存在しない検知版・シート別PDFへのpin/lease作成が空の世代フォルダを残す問題を解消した。
- 手動pinと保持整理の競合を解消した。
- ページ構成のプレビュー・undo保存・復元が別々の状態を参照し得た処理を、復元時の単一構造ロックへ統合した。
- 廃止済み出力先、不正な並び順・番号方式・ページ範囲、重複ページID、別言語・別資料パックの履歴を安全に処理または拒否するようにした。
- `retainSourceVersions`のコード内フォールバックを配布既定値の5世代に統一した。

## 回帰確認

`app/tools/history-logic-selfcheck.ps1` は一時ワークスペースと実ファイルを使い、次を確認する。

- 破損した保持原稿の検出・修復と、修復後のハッシュ一致
- 未完成世代の一覧除外
- キャッシュを温めた後に実体を削除した場合の無効化
- 存在しない資産へのpin/lease拒否と、空フォルダ非生成

`app/tools/custom-pack-workflow-selfcheck.ps1` は、廃止済みの任意出力先を含むページ構成履歴が未振り分けへ正規化されること、復元直前のundo版が残ること、重複ページIDを含む破損履歴が拒否されることを確認する。

これらを`app/tools/ci-selfcheck.ps1`へ組み込み、既存の差分、最終組版、資料パック、配布物スモークテストと同時に実行する。
